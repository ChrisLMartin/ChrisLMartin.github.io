Staging an ARM-to-Bicep migration

How to prove deployment parity with a parallel path and a sandbox before switching live environments.

A migration from ARM JSON to Bicep can change the authoring language, module boundaries and release process all at once. In a migration I helped design and validate, we kept the existing deployment path available while building a second path, then treated the engine switch as its own change.

Hold the deployment inputs steady

Start from the parameters the existing pipelines actually use. Generate equivalent Bicep parameters and check the generated files in CI so they cannot quietly drift from their source. Keep existing modules where you can, then convert them in small groups with their own comparison against the current output. This makes it easier to tell whether a difference came from the new authoring language or from an intentional platform change.

Prove the candidate in layers

  1. Compare inputs and compiled resources. Examine meaningful property differences. Establish a baseline before interpreting changes in what-if output.
  2. Deploy both paths in the same sandbox. Start with the existing engine, redeploy with Bicep, and verify the resulting resources and permissions. A preview alone cannot establish runtime parity.
  3. Run read-only previews across representative environments. Inspect changes by resource and property. Investigate unexpected creates or deletes, and distinguish recurring preview noise from changes the deployment would actually make.

Make cutover an explicit decision

Keep the existing engine as the default while the replacement is being reviewed. Switch in small groups when the preview evidence and approval checks are ready. Give deliberate infrastructure changes their own review so they are visible independently of the migration. Plan how to pause or revert before promoting the next group.

We exercised the parallel path in a sandbox and ran broad what-if comparisons ahead of cutover. The sample that mattered most was an actual redeploy in a controlled environment, because it tested the effects that previews could only predict.
